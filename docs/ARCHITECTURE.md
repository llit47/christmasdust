# Architecture

One Node.js 24 process serves Express and static ES modules. No database or build step.
Steam discovery (10 minutes) collects AppID 10 / cstrike metadata in eight broad regional requests plus at most ten global targeted requests: up to five exact map filters from `config/christmas-maps.json`, then safe `name_match` terms from `config/detection.json`. The map filter is defined by [Steam's server browser filter API](https://partner.steamgames.com/doc/api/isteammatchmakingservers); its behavior through the Web API endpoint has not been verified with a live key. Targets are fixed, bounded and never visitor-controlled. Capped results, unavailable maps and unindexed servers can still be missed. A targeted hit is only one weak signal: returned metadata must pass the normal classifier. GameDig counterstrike16 queries (45 seconds) target only classified candidates and operator includes. Both jobs serialize through one coordinator; a busy job is skipped, never piled up. Public reads only read memory.

The classifier tokenizes normalized name, Steam tags, optional description and map. `x-mas` and `x_mas` normalize to `xmas`; unrelated substrings do not match. Exact strong catalog maps and explicit Christmas/Xmas naming yield high confidence. Exact probable catalog maps require a separate identity signal; a weak `winter` or `holiday` hostname can provide that corroboration. A generic snow/ice/winter map or weak seasonal text alone never qualifies, even if a targeted query returned it. The score and structured signals explain the outcome; curated inclusion remains an operator decision with its own confidence label. `config/christmas-maps.json` is a small audited map catalog: add a verified map to `strong` for unambiguous Christmas maps, or `probable` when another signal should be required. Initial entries have published CS 1.6 map pages: [de_christmas](https://gamebanana.com/mods/346635), [de_dust2_xmas](https://gamebanana.com/mods/83799), [awp_christmas](https://gamebanana.com/mods/87180), [de_dust2_christmas2](https://gamebanana.com/mods/83715), and [deathrun_jinglebells](https://gamebanana.com/mods/91007). This score describes Christmas relevance only; fake-player and server-farm analysis is separate future work.

Discovery merges candidates, never replaces the entire cache. Partial regional or targeted success remains useful. Steam `gametype` tags remain trusted discovery evidence across GameDig name/map queries, which cannot observe those tags. A later Steam record with an explicit updated tag value replaces that evidence; an omitted tag field does not. A failed live query retains previous metadata and increments misses; three consecutive misses mark offline. Online is a last-observed state, not a guarantee. Cached data ages visibly. An automatic candidate is hidden after one complete observation with a non-matching name and map, then removed after a second consecutive complete non-match from discovery or a successful live query. Incomplete name/map responses and query failures do not count. Hidden candidates also expire after the configured retention period (seven days by default) without positive theme evidence, even if incomplete responses keep arriving. Other non-curated servers expire after that period without discovery or successful queries; the total candidate count is capped. Includes remain monitored regardless of theme; exclusions win over includes.

Steam Networking / FakeIP endpoints are unsupported. They require a distinct Steam networking resolution and query path and are intentionally rejected by the public IPv4 validator rather than sent ordinary GameDig UDP queries.

Snapshots use a versioned schema, temporary file, fsync, atomic rename and directory fsync. Startup restores the last snapshot before accepting traffic. Memory can continue serving if disk persistence fails, with degraded health. Readiness means initialization completed; freshness is reported separately so an upstream outage does not cause restart loops.

Visitor country comes from a local MMDB lookup or an explicitly trusted proxy's sanitized CF-IPCountry. The API never returns visitor coordinates. The opt-in browser geolocation result remains in memory; Haversine distance is computed locally. Recommendation orders Christmas relevance first, then same-country, geographic distance when available, online state, available slots and population. Distance is approximate and never network ping. GameDig latency is the monitor-to-server query latency.

External adapters (discovery, query, GeoIP), storage and clock are injected for offline tests. The frontend uses text nodes for external metadata and builds Steam links only from validated endpoints.
